# PCT Property Intelligence — Phase 1 Website

Static HTML/CSS/JS site. No build step, no dependencies, no framework —
open any `.html` file directly in a browser, or upload the whole folder to
any static host (Netlify, Cloudflare Pages, GitHub Pages, standard cPanel
hosting, etc.).

## Structure

```
index.html                 Homepage
about.html                 About PCT
services.html               Services overview
services/*.html             7 individual service pages
contact.html                Enquiry / quote request form
resources.html               Resources hub
resources/*.html             3 published articles
portal.html                  Client Portal concept (coming soon)
privacy-policy.html, terms.html, cookie-policy.html
404.html
sitemap.xml, robots.txt
assets/css/style.css         Design system (single stylesheet)
assets/js/main.js            Nav, cookie banner, form handling, animations
```

## Before going live — action items

1. **Contact details.** The enquiry form, footer, legal pages and schema use
   `info@pctpropertyintelligence.co.uk` (`BUSINESS_EMAIL` in `build.py`, plus
   the mailto fallback in `assets/js/main.js`). Add a phone number to
   `contact.html` and the footer (`assets` templates were generated by `build_pages.py`/`build.py`
   — edit those and regenerate, or edit the HTML directly).
2. **Form backend.** The quote form is pre-wired for **Netlify Forms**
   (`data-netlify="true"` + hidden `form-name` field) — if you host on
   Netlify, submissions just work, no code needed. On any other host, it
   currently falls back to opening a pre-filled `mailto:` link. Swap in a
   real backend/CRM in Phase 2 (see brief §29–31).
3. **Analytics.** A GA4 loader stub sits in `build.py`'s `GA_STUB` (and thus
   in every page's `<head>`), disabled until a visitor accepts the cookie
   banner. Add your real Measurement ID and uncomment the loader lines.
4. **Imagery.** Photos now come from `images/` (Higgsfield-generated) and
   `..\Stock photos` (PCT's own inspection photos). Web-sized copies are built
   into `assets/img` by `tools/process-images.ps1` — re-run it after adding or
   replacing a photo, then register the new key in `PHOTOS` in `build.py`.
   Retrofit Assessment deliberately still uses a placeholder (`ph(...)`).
   The logo files in `assets/img/logo-*.png` are cut from `logo.jpeg` and
   `embroidery logo.jpeg`; the favicon is a provisional roofline symbol.
5. **Legal pages.** `privacy-policy.html` and `terms.html` carry an HTML
   comment flagging where to add a company registration number and ICO
   registration reference once obtained — nothing was fabricated.
6. **Domain & canonical URLs.** `DOMAIN` in `build.py` is already set to
   `https://pctpropertyintelligence.co.uk` for canonical tags, Open Graph
   tags, JSON-LD and the sitemap.

## Regenerating the site

`build.py` and `build_pages.py` are the source of truth (kept out of the
delivered zip, but included if you want to keep editing programmatically).
Edit content in `build_pages.py`, then run:

```
powershell -ExecutionPolicy Bypass -File tools\process-images.ps1   # only when photos change
python build_pages.py
```

Design system: PCTPI Navy `#0B1F33` + Copper `#C46A32` (button fills use the
deeper `#A8561F` so white text passes WCAG AA). Montserrat/Inter are
placeholder typefaces until a final brand font is chosen.

This regenerates every HTML file with consistent header/nav/footer/SEO
metadata. Hand-editing the generated `.html` files directly also works
fine for small tweaks — nothing about deployment depends on the generator.

## Phase 1 status (per project brief §39)

### Completed
- Homepage, About, Services overview, 7 individual service pages, Contact
  page with a full enquiry/quote form, Resources hub with 3 published
  articles, Client Portal concept page, Privacy Policy, Terms, Cookie
  Policy, and a 404 page.
- Consistent header/nav (with a services mega-dropdown grouped into the
  four service categories from §14), consistent footer, cookie-consent
  banner, and reveal-on-scroll micro-animation.
- "Available now" vs "Coming soon" badges applied per-service, based on
  what equipment/qualifications are actually in place today (EPC / Domestic
  Energy Assessment — ABBE-qualified DEA — plus drone, roof and gutter
  inspection, property documentation and photography are live; Retrofit
  Assessment is marked coming soon).
- A "See exactly what you receive" illustrative report mock-up, and a
  Client Portal preview mock-up, to communicate the long-term vision
  without overbuilding functionality that doesn't exist yet.
- Mobile-responsive throughout (single breakpoint-driven CSS, no separate
  mobile templates); accessible landmarks, skip link, visible focus states,
  reduced-motion support.
- SEO foundations: unique title/description per page, canonical URLs,
  Open Graph/Twitter tags, JSON-LD (ProfessionalService on the homepage,
  Service on each service page, Article on each resource article),
  sitemap.xml, robots.txt.
- Analytics wired but inert until cookie consent (privacy-by-default).

### Decisions
- **Static HTML/CSS/JS**, not a framework — fastest to launch, hosts
  anywhere, and avoids overbuilding a Phase-1 brochure site (per §40).
  The architecture (Customer → Property → Job → Inspection → Report →
  Media) is left for Phase 3 onward, where a real backend/framework
  becomes necessary for the customer portal.
- **Placeholder imagery** rather than generic stock photography, per the
  brief's explicit instruction to avoid a "stock" look — every image slot
  is a clearly labelled placeholder ready to be swapped for real
  photography, drone stills and report screenshots.
- **Gutter service shows two badges**: inspection "available", cleaning
  "coming soon" (equipment not yet purchased). See `badges` in `build.py`.
- **No fabricated credentials.** Only the Flyer ID / Operator ID / DJI
  Mini 5 / Kärcher K4 already confirmed in the brief appear as trust
  signals; no insurance, memberships or certifications are claimed.
- Worcestershire used as the primary service area (from the brief's SEO
  keyword list), phrased as "Worcestershire and surrounding areas" so nearby
  enquiries aren't discouraged.

### Outstanding (deliberately deferred to later phases)
- No phone number is displayed anywhere — none was provided, and inventing
  one felt worse than omitting it. Add it to `contact.html`/footer when
  available.
- Form submissions are not yet captured anywhere automated beyond Netlify
  Forms (if hosted there) or a mailto fallback — proper lead tracking is
  explicitly Phase 2 (§29–31).
- No customer accounts, login, or real report data — the Client Portal
  page is a concept/preview only, as intended for Phase 1.
- No dedicated landing pages per audience segment (homeowners, landlords,
  etc.) — kept as a single descriptive strip on the homepage to avoid thin
  pages; can be split out once there's real content to differentiate them.
- Photo upload on the enquiry form is a labelled "coming soon" notice
  rather than a working uploader (needs a backend).
- Google Analytics needs a real Measurement ID before it does anything.

### Next phase
Phase 2 (Lead Generation & Customer Conversion) adds: a proper quote
system with combinable services, service-area pages for the initial
market, and lead tracking suitable for eventual CRM integration — all of
which this Phase 1 build was structured not to block (forms, service
data and page structure are already organised by service/category so
Phase 2 can extend them rather than rebuild them).
